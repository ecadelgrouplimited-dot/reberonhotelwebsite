| ADR-028 | 2026-11-07 | Owner finance (`GET /reports/finance`, `GET /owner/brief/insights`): revenue is recognised on the night slept (rooms), the day settled (POS, desk F&B, spa) and the folio date (extras, cancellation/no-show fees); discounts, goodwill credits and write-offs are allowances that reduce net revenue; "collected" is every rail (room payments + non-folio POS + health club) minus refunds, and POS bills sent to a room folio are never counted as cash. | ADR-029 | 2026-11-08 | The House is an installable offline-first PWA: a hand-written service worker (`apps/admin/public/sw.js`, versioned per build) caches code cache-first, pages network-first with a 3.5 s fallback, and API reads network-first per signed-in user (`x-rb-cache` marks saved copies); RSC fetches are never cached so Next falls back to a full load answered from the page cache. Writes are never cached: `lib/api.ts` stamps every admin write with an Idempotency-Key and, when the network fails, stores it in an IndexedDB outbox (FormData uploads included) that the service worker replays on reconnect or via Background Sync; the API's global `IdempotencyInterceptor` (Redis, 24 h) makes replays exactly-once. Failed replays (4xx) stay in the Sync Center with the server's reason — no silent conflict resolution. Web Push uses `web-push` + VAPID (env or generated once, sealed) and the same owner-edited alert rules as the in-app pop-ups, never notifying the person who acted. "Download for offline" opens each permitted screen in a hidden same-origin frame (X-Frame-Options → SAMEORIGIN) | The hotel's connection drops; the desk, POS and housekeeping must keep working and nothing may be double-booked or double-charged when the queue replays | Accepted |
| ADR-030 | 2026-11-08 | Every screen works offline without having been opened: the admin build lists all routes from `app/(house)` (`NEXT_PUBLIC_APP_ROUTES`); on sign-in and on each new version the service worker saves every page and every code file it references, and detail routes are saved once with a placeholder id as a template whose id is swapped in for any record. The worker learns which API reads each screen makes and refreshes them every 15 minutes while online; dated reads fall back to the newest saved copy. Offline edits are shown immediately and on every saved copy until synced (generic: `PATCH …/<id>` merges known fields, `DELETE …/<id>` removes, check-in/out, no-show, cancel, confirm and POS settle set the known status). The POS keeps selling offline with a provisional slip; the numbered receipt is issued on sync | Staff could only use screens they had happened to open online; the till must not stop | Accepted |
| ADR-031 | 2026-11-08 | One print and export path for the whole House. `lib/print.ts` copies a screen, dialog or table into a hidden frame as an A4 document with the hotel letterhead (logo, name and contact from the public site settings, cached for offline), title, period, who printed it and when, page numbers in the page margin, and no buttons, filters or tabs; Ctrl/Cmd+P uses it too. `lib/export.ts` turns one table spec into Excel (.xlsx written in the browser, no dependency: letterhead rows, styled header, real numbers with UGX/USD formats, totals, frozen header, filters), CSV (plain data, numbers unformatted) or the same table as a branded PDF. | ADR-032 | 2026-11-08 | Website editing: the page builder's preview talks to the editor (`postMessage`, House origin only): clicking a section in the draft preview opens that block, selecting a block scrolls the preview to it, and saves refresh the preview in place instead of reloading it. | ADR-034 | 2026-11-23 | The House behaves like a desktop OS. | ADR-036 | 2026-11-23 | Quick changes are reversible in place: room status changes (Rack, Housekeeping, Today board) and inbox status/assignment changes show a toast with Undo, and Ctrl/⌘+Z undoes the last one for 7 s (screens with their own undo, like the page builder, opt out with `data-own-undo`); an undo is an ordinary audited change back to the previous value. | ADR-038 | 2026-11-23 | Every printable document shares one letterhead (`apps/api/src/modules/documents/letterhead.ts`): the RH monogram and the hotel's name, legal name, address, phone, email, TIN and footer from Settings — receipts, invoices, refunds, statements and quotations (existing renderer), plus store requisition vouchers (A4 with approval trail and signature boxes, 80 mm) and POS bills and kitchen tickets (80 mm, thermal-friendly), which were plain and hard-coded the hotel name.
